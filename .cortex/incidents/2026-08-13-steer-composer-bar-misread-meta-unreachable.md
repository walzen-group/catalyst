## Root cause

Three gaps, one tool surface and two instruction gaps.

1. **Tool: the pre-send composer check fails honestly but its failure surface is a dead end with a misleading face** — `catalyst-v2-dispatch/src/deliver.mjs` (check) and `src/screens.mjs` (`ompComposerText`). On a bar-less settled screen the delivery returns `failed` with "the agent may be on a dialog" — a hypothesis phrased as the diagnosis — without consulting the agent's herdr status (`agent get`: idle/working/blocked), without the hint the blocked-agent path carries (`herdrResolutionHint`), and without any caller guidance. The 08-03 fix designed the honest failure ("nothing is sent blind"); it never designed what the failure means to a caller. This wave is its first live exercise, six times. Compounding: steer failure specimens are not persisted — the failures ledger records step/detail/at only — so the orchestrator had no way to see what the pane actually showed, and a post-hoc diagnosis from the tool's own records is impossible.

2. **Instructions: probe-and-verify does not cover a steer whose delivery tool fails pre-send** — `catalyst-v2-orchestrating-delegates/SKILL.md` (the 08-03-meta-retirement-misdiagnosis fix) and `catalyst-v2-running-a-meta-agent/SKILL.md`. The discipline covers status reads (META QUIESCENT) and steer probes that deliver; it never says a delivery-tool failure is a channel/tooling defect, not liveness evidence. Nothing names the working channels when steer cannot deliver: the agent's own outgoing steer (which delivered the hand-back minutes later), the user channel (which the user demonstrated), `herdr agent attach`. Nothing requires asking the user before replacing a meta whose pane the user is actively using. The orchestrator followed the letter (it probed) and still misjudged, because the probe channel itself failed and the failure's meaning was undefined.

3. **Instructions: the wait died at the harness timeout and the re-arm was never executed** — `catalyst-v2-running-a-meta-agent/SKILL.md`, `catalyst-v2-multiplexer-agent-ops/SKILL.md`. The wait ran in a shape subject to the harness's 300 s tool-call timeout and died; the meta planned the re-arm but parked without running it, leaving the wave unwatched and itself asleep on stale knowledge. The prose ban on foreground blocking waits ("Banned wait shapes") exists but the mechanical enforcer — the `foreground-wait-guard` omp extension — is not installed on this host (verified: `~/.omp/agent/extensions/` lacks it; present are guard-disk, guard-push, herdr-omp-agent-state, kimi-usage, neuralwatt-usage, sleep-guard). The 08-09/08-11 enforcement applies only where the extension exists; here the rule is prose-only and adherence failed.

## Fix

Report-only, per user scope: diagnose and name what a repair would touch; no instruction edits, no tool code, no replay, no test in this dispatch. A repair dispatch acts on the incident later.

1. **Tool** (`catalyst-v2-dispatch/src/deliver.mjs`, `src/screens.mjs`, `src/steer.mjs`, `src/failures.mjs`). On a bar-less pre-send read: read the agent's herdr status and report the distinction — `blocked` (dialog up; keep the herdr hint), `working` (delivery tool cannot read the screen; report as a channel/tooling defect with the status), `idle` (same). Add the settled-screen specimen to the failure record (the failures ledger currently records step/detail/at only). Consider a bounded wait for the omp bar mirroring the claude path's `waitForComposer` — the 08-03 open item — instead of a single settled read. Verify with the unit suite plus live steers against a dialog-up pane and a working pane.
2. **Instructions** (`catalyst-v2-orchestrating-delegates/SKILL.md`, `catalyst-v2-running-a-meta-agent/SKILL.md`). Extend the probe-and-verify text at the delivery layer: a steer delivery failure is a channel/tooling defect, never liveness evidence; when steer cannot deliver, the channels to try before any replacement are the agent's own outgoing steer, the user channel (ask the user — the user is present and uses that pane), and `herdr agent attach`; a replacement is justified only when every channel answers nothing AND no hand-back exists AND the incumbent's session reads exited/gone. Same spirit as the never-two-metas rule; this incident is the delivery-layer row it was missing.
3. **Instructions + operational** (`catalyst-v2-running-a-meta-agent/SKILL.md`, `catalyst-v2-multiplexer-agent-ops/SKILL.md`, host extensions). The wait must be armed as a background job of the meta's own harness or with the harness tool timeout raised at the call site, and the re-arm must happen in the same turn the death is observed — never park with a planned-but-unexecuted re-arm. The wake prescription's "(Claude Code: run_in_background: true)" parenthetical is claude-specific; it does not tell an omp meta how to background a wait. On this host: install `foreground-wait-guard` for mechanical enforcement, or pin the backgrounding rule for omp metas explicitly in the skill.
4. **Memory.** At repair time, drop a `feedback-*` note (c2m) generalizing "a steer delivery failure is a channel/tooling defect, not agent unreachability; never replace a meta on a delivery-tool failure without exhausting the working channels" — the lesson generalizes beyond this wave.
